## 二、P0(必须处理)

### P0-1 发布 tarball 缺失 cordis.patch.yml,疑似安装即断
`package.json` 的 `files` 白名单未包含 `cordis.patch.yml`,而 `dsh.bundle.patch` 指向它;`tar -tzf dist/prdcraft-3.0.0.tgz` 确认包内无此文件。DSH 机制:bundle 的 patch 加载失败 → 整个 bundle 被跳过(skippedBundles)。**修复:files 加入 `"cordis.patch.yml"` 并重打包;verify.mjs 增加 tarball 内容断言。**

### P0-2 skills/ 混入 2 个未文档化、未适配的技能(判定为遗漏而非有意)
工作区 skills/ 有 **7** 个目录,README/package.json 声称 **5** 个(3.0.0 tarball 也只打了 5 个,但按当前工作区重打包会变成 7 个)。index.js 无白名单、扫描全部子目录 → 静默注册:
- **interaction-prd-main**(注册名 `interaction-prd`):上游 comeonzhj/interaction-prd v0.8.0 整包仓库快照。含 .gitignore、AGENTS.md、ITERATION_LOG.md、agents/openai.yaml、外部渠道安装文档、docs/images 截图等仓库维护资产;零 DSH 适配(无附注);自有工作区约定 + 要求 npm install(html2canvas/marked/mermaid),与 README「零运行时依赖」直接矛盾;frontmatter name ≠ 目录名。
- **prd-generator**:上游 mpf0418/prd-generator v1.0.0 原样拷贝。description 仍为多行 `>` 折叠块(未走 bake 规范化);skill-card.md:35-37 引用断链 `artifact/references/*`;无 DSH 附注。

证据链:全仓 grep 两名零引用 / tools/appendices/ 只有 4 个附录 / README 技能清单、致谢均未提及。
**修复(二选一):移出 skills/(或 index.js 加发布白名单);或走完整 bake 流程(附录+分工让位条款+frontmatter 规范化+清理仓库资产)并更新 README 5→7。**

### P0-3 触发冲突:"写 PRD" 同时命中 prd-craft 与 prd-generator
prd-generator 描述明写「用户提到写PRD、写产品需求文档…时触发」,与 prd-craft「中文 PRD 默认入口」正面相撞;prd-generator 无任何分工/让位声明(对照:prd-workflow 有明确让位条款)。上游 prd-workflow/SKILL.md:492 把"简单功能/紧急需求"导流给 prd-generator,而 prd-craft 路由表未镜像该规则 → 分流死角。

### P0-4 prd-workflow「直接运行代码」路径实际不可用(附注承诺失效)
1. **CJS/ESM 冲突**:包根 `"type": "module"`,workflows/*.js 全是 CommonJS。实测 `CUSTOM_OUTPUT_DIR=... node workflows/main.js` 启动即崩:`require is not defined in ES module scope`(main.js:14)。
2. **门禁断裂**:quality_gates.js 只定义 gate1-4(文件头自称"草稿"),而 flowchart/design/prototype/export/quality 模块调用 gate5-9,`pass()` 对未定义 gate 直接 throw 且无 try/catch → full 流程跑到 flowchart 必然整体失败(实测复现"未知门禁:gate5_flowchart")。
**修复:skills/prd-workflow/ 下加 `{"type":"commonjs"}` 的 package.json(需同步入打包清单);补齐 gate5-9 或降级为 warn。**
